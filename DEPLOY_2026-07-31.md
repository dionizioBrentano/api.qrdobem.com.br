# Deploy da API — via GitHub + cPanel

Este documento cobre dois cenários: a **primeira configuração** (feita uma única vez) e o **deploy do dia a dia** (dois cliques).

---

# PARTE 1 — Configuração inicial (só uma vez)

## 1.1 Dar acesso do servidor ao repositório privado

O cPanel precisa conseguir clonar um repositório privado. Isso se resolve com uma chave SSH — o cPanel gera, o GitHub autoriza.

**No cPanel:**

1. SSH Access → Manage SSH Keys → Generate a New Key
2. Nome: `github_deploy`. **Deixe a senha em branco** — com passphrase o clone trava pedindo senha.
3. Volte para Manage SSH Keys → na chave criada, clique em **Manage** → **Authorize**
4. Na mesma tela, clique em **View/Download** da chave **pública** e copie o conteúdo inteiro (começa com `ssh-rsa` ou `ssh-ed25519`)

**No GitHub**, no repositório `api.qrdobem.com.br`:

5. Settings → Deploy keys → Add deploy key
6. Title: `cPanel hospedameusite`. Cole a chave pública. **Não** marque "Allow write access" — o servidor só precisa ler.

Repita o passo 6 no repositório do frontend, colando a **mesma** chave.

## 1.2 Clonar o repositório no servidor

cPanel → **Git™ Version Control** → **Create**:

- Ative **Clone a Repository**
- **Clone URL:** `git@github.com:dionizioBrentano/api.qrdobem.com.br.git`
  (formato SSH, não HTTPS — o HTTPS pediria usuário e senha)
- **Repository Path:** `/home/SEU_USUARIO/repos/api-qrdobem`
- **Repository Name:** `API QR do Bem`

> O caminho do repositório fica **fora** da pasta do site. Quem copia os arquivos para `~/api.qrdobem.com.br` é o `.cpanel.yml`. Clonar direto por cima do site exporia a pasta `.git` na web.

Clique em Create e espere o clone terminar.

## 1.3 Primeiro deploy

Git Version Control → no repositório criado, **Manage** → aba **Pull or Deploy** → **Deploy HEAD Commit**.

Isso executa as tarefas do `.cpanel.yml`: copia `app/`, `config/`, `routes/`, `database/`, `public/` etc. para `~/api.qrdobem.com.br` e limpa os caches.

Se o deploy falhar dizendo que não encontrou o PHP, descubra o caminho certo por SSH:

```bash
which php
```

E ajuste as últimas linhas do `.cpanel.yml` com o caminho retornado.

## 1.4 Instalar a biblioteca do QR Code (SSH, uma vez)

O `.cpanel.yml` copia o `composer.json`, mas não instala dependência — isso é decisão sua, não do deploy.

```bash
cd ~/api.qrdobem.com.br
composer update bacon/bacon-qr-code --no-dev -o
```

Use `composer update` **nesta primeira vez**: o `composer.lock` ainda não conhece o pacote e o `install` recusaria por estar fora de sincronia. Nos próximos deploys, `composer install --no-dev -o` basta.

Confirme:

```bash
ls vendor/bacon/bacon-qr-code
```

Se o composer reclamar de extensão faltando (`ext-xmlwriter`, `ext-iconv`), habilite em cPanel → Select PHP Version → Extensions e rode de novo.

> Enquanto o pacote não estiver instalado a API **não quebra**: cria a entidade normalmente e devolve `qr_code_base64: null`, registrando um aviso no log. O frontend mostra um aviso amarelo no lugar da imagem. Isso é proposital, para um deploy pela metade não derrubar o sistema.

## 1.5 Ajustar o `.env` do servidor (SSH)

O `.env` nunca é copiado pelo deploy — ele vive só no servidor, com as senhas.

```bash
nano ~/api.qrdobem.com.br/.env
```

Acrescente no final:

```env
QR_PUBLIC_BASE_URL=https://qrdobem.com.br
QR_PUBLIC_PATH_PREFIX=q
QR_SIZE=512
QR_MARGIN=4
QR_ERROR_CORRECTION=Q
```

Salve (Ctrl+O, Enter, Ctrl+X) e aplique:

```bash
cd ~/api.qrdobem.com.br
php artisan config:cache
php artisan route:cache
```

## 1.6 Corrigir as entidades já existentes no banco

O model `Entity` não tinha `status` no `$fillable`. Resultado: **toda entidade criada até hoje foi gravada como `pending_term`**, mesmo com o termo aceito. Como o endpoint público agora exige `status = 'active'`, esses QR Codes retornariam 404.

Confira primeiro quantas linhas serão afetadas (phpMyAdmin ou SSH):

```sql
SELECT COUNT(*) FROM entities
WHERE is_active = 1 AND status = 'pending_term' AND deleted_at IS NULL;
```

Se o número fizer sentido, rode:

```sql
UPDATE entities SET status = 'active'
WHERE is_active = 1 AND status = 'pending_term' AND deleted_at IS NULL;
```

Este é o único passo que altera dados. Rode uma vez só.

# PARTE 2 — Deploy do dia a dia

Depois da configuração acima, publicar uma alteração é:

1. `git push` da sua máquina
2. cPanel → Git Version Control → Manage → **Update from Remote**
3. **Deploy HEAD Commit**

Só isso. O `.cpanel.yml` copia os arquivos e limpa os caches sozinho.

**Quando você adicionar uma dependência nova no `composer.json`**, entre uma vez por SSH depois do deploy:

```bash
cd ~/api.qrdobem.com.br && composer install --no-dev -o
```

**Quando criar uma migration nova:**

```bash
cd ~/api.qrdobem.com.br && php artisan migrate --force
```

# PARTE 3 — Testes de aceitação

Com um token válido no header `Authorization: Bearer <token>`:

1. **QR real na criação** — `POST /api/entities` deve devolver `qr_code_base64` começando com `data:image/svg+xml;base64,`. Colado na barra do navegador, precisa aparecer um QR de verdade — não mais o texto `QR_CODE_MOCK`.

2. **Endpoint dedicado** — abra logado no navegador:
   `https://api.qrdobem.com.br/api/entities/{unique_code}/qrcode?format=svg`
   Escanear com o celular deve abrir `https://qrdobem.com.br/q/{unique_code}`.

3. **Isolamento** — pedir o QR de uma entidade de outra organização deve retornar 403.

4. **E-mail do tenant** — faça login e confira:
   ```sql
   SELECT id, name, email FROM tenants ORDER BY id DESC LIMIT 5;
   ```
   O campo `email` não pode mais estar vazio.

5. **add-quota** — `POST /api/admin/tenants/1/add-quota` deve retornar 404 (a rota não existe mais), e não 500.

6. **Página pública** — `GET /api/entities/{unique_code}` deve responder 200 depois do passo 1.6.

7. **Fluxo completo pelo site** — perfil → CPF → OTP → endereço → criar QR Code com o termo aceito → escanear → mandar mensagem → ver na caixa de entrada.

# Se algo der errado

**Deploy não executa as tarefas** — o `.cpanel.yml` precisa estar na raiz do repositório e no branch que está com checkout (`main`). Confira em Git Version Control se o branch é `main`.

**Erro 500 depois do deploy** — veja a causa real:
```bash
tail -50 ~/api.qrdobem.com.br/storage/logs/laravel.log
```

**Rota nova dá 404** — cache de rotas velho:
```bash
cd ~/api.qrdobem.com.br && php artisan route:clear && php artisan route:cache
```

**Voltar para a versão anterior** — o deploy antigo continua no histórico do git:
```bash
cd ~/repos/api-qrdobem
git log --oneline
git checkout <hash-anterior>
```
Depois faça Deploy HEAD Commit de novo no painel.
