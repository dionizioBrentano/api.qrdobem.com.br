## 2. Instalar a biblioteca de QR Code (SSH)

```bash
cd ~/api.qrdobem.com.br
composer update bacon/bacon-qr-code --no-dev -o
```

Use `composer update`, **não** `composer install` — o `composer.lock` ainda não conhece o pacote novo e o `install` vai reclamar que está fora de sincronia.

Se o composer acusar extensão faltando (`ext-xmlwriter` ou `ext-iconv`), habilite no cPanel → Select PHP Version → Extensions, e rode o comando de novo.

**Como saber se deu certo:**

```bash
ls vendor/bacon/bacon-qr-code
```

Enquanto o pacote não estiver instalado, a API não quebra: ela cria a entidade normalmente e devolve `qr_code_base64: null`, registrando um aviso em `storage/logs/`. Isso é proposital, para o deploy não derrubar o sistema no meio do caminho.

## 3. Adicionar ao `.env` do servidor

```env
QR_PUBLIC_BASE_URL=https://qrdobem.com.br
QR_PUBLIC_PATH_PREFIX=q
QR_SIZE=512
QR_MARGIN=4
QR_ERROR_CORRECTION=Q
```

A URL pública saiu do código e virou configuração — cada frontend whitelabel pode apontar para o próprio domínio sem tocar na API.

## 5. Corrigir as entidades já existentes no banco

O model `Entity` não tinha `status` no `$fillable`. Resultado: **toda entidade criada até hoje foi gravada como `pending_term`**, mesmo com o termo aceito. Como o endpoint público agora exige `status = 'active'`, esses QR Codes retornariam 404.

Rode uma vez, via phpMyAdmin ou SSH:

```sql
UPDATE entities
SET status = 'active'
WHERE is_active = 1
  AND status = 'pending_term'
  AND deleted_at IS NULL;
```

Confira antes quantas linhas serão afetadas:

```sql
SELECT COUNT(*) FROM entities WHERE is_active = 1 AND status = 'pending_term' AND deleted_at IS NULL;
```

## 6. Testes de aceitação

Com um token válido no header `Authorization: Bearer <token>`:

1. **QR real na criação** — `POST /api/entities` deve devolver `qr_code_base64` começando com `data:image/svg+xml;base64,` e um SVG que, colado no navegador, aparece como QR de verdade (não mais `QR_CODE_MOCK`).
2. **Endpoint dedicado** — abrir no navegador logado:
   `https://api.qrdobem.com.br/api/entities/{unique_code}/qrcode?format=svg`
   Deve renderizar a imagem. Escanear com o celular deve abrir `https://qrdobem.com.br/q/{unique_code}`.
3. **Isolamento** — pedir o QR de uma entidade de outra organização deve retornar 403.
4. **Email do tenant** — fazer login e conferir no banco:
   `SELECT id, name, email FROM tenants ORDER BY id DESC LIMIT 5;`
   O campo `email` não pode mais estar vazio (o backfill preenche no primeiro request de quem já tinha conta).
5. **add-quota** — `POST /api/admin/tenants/1/add-quota` deve retornar 404 (rota não existe mais), e não 500.
6. **Página pública** — `GET /api/entities/{unique_code}` deve continuar respondendo 200 depois do passo 5 do banco.
